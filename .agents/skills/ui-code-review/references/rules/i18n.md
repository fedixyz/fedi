# i18n: no hardcoded user-facing strings

Every string a user can see must go through i18n, never be hardcoded.

- covers screen copy, button labels, toast and overlay text, and error messages surfaced to the UI or to miniapp callers
- use `t()` with a key defined in `ui/common/localization/en/common.json`
- a hardcoded user-facing English sentence is a defect, not a nit: the app ships in ~20 locales, so raw English is broken UI for most users
- proper nouns are not copy. Network names (`Signet`, `Regtest`), currency and unit codes (`BTC`, `sats`), brand names, and values that arrive as data (a federation's name, a username) all stay raw. If a Spanish translator handed the string alone would return the same characters, a key adds indirection and nothing else. The *sentence around* the token still needs one: "This federation uses {{network}} sats" is copy, `{{network}}` is not
- applies to new code, not only regressions
- severity is `principles.md` section 4's call, not this rule's. Weigh who actually reaches the string before you grade it
